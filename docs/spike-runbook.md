# Spike runbook

How to run each step of [spike-plan.md](spike-plan.md) with the spike app and the Mac. The plan says what to find out and what counts as a pass; this page says which button to tap, what the log shows, which measurements are recorded and which fixture files are saved. Results go in [spike-findings.md](spike-findings.md).

How to read the tables:

- **Do** is *tab › section › button* in the spike app (*SB Spike* on the phone), or a camera menu, or **Mac** with the command to run for the code-free steps. The app has five tabs: Wired, Wi-Fi, Bluetooth, Background and Log.
- **Log shows** is what appears on the Log tab. Every button writes there, with the app state (foreground, background, locked) where it matters. The log is kept across launches in `Documents/spike-log.jsonl`.
- **Measurements** are the names recorded on the Log tab. `<net>` is `ap` or `lan`, from the Wi-Fi tab's *Network* picker. On day 10, *Copy measurements table* fills the plan's table from the latest value of each name; the "Day 10: export" section lists which name feeds which cell.
- **Fixtures** are saved on the phone under `Documents/fixtures/a7c2/` and go in the repo under `Fixtures/a7c2/` with the same path: `usb/deviceinfo.bin` on the phone is `Fixtures/a7c2/usb/deviceinfo.bin` in the repo. Saving again replaces the earlier file of the same name. See [Fixtures/README.md](../Fixtures/README.md).
- The Wired tab runs one operation at a time: the other buttons are disabled while it runs, and the overlay at the bottom shows it with a *Stop* button, which ends loops at the next file or chunk. The Wi-Fi tab also runs one camera operation at a time.

The spike app compiles with Xcode 27 for iPhone (the unsigned build in `.github/workflows/spike-build.yml`), but it has not yet run on a phone. Behaviour that only a device can confirm is commented `verify on day 1` in the sources.

## Photos albums (no camera; best on 1–2 Nov; not in the plan)

Added on 1 Nov for a product decision: every import should go into an album in Photos. The proposal asks for add-only access (the small prompt) and puts imports in a per-camera album. Apple doesn't document whether an add-only app can create an album or find it again. One forum report says both calls bring up the full read/write prompt. With limited access, a WWDC21 session says apps can create, fetch and update their own albums since iOS 15, but Apple's privacy article still says they can't. Saving while the phone is locked is documented only for Lock Screen camera extensions.

Everything is in Background › *Photos albums, no camera*. The test photos are teal JPEGs labelled "Shutter Bridge spike test". Every line in the log starts with `photos:` and shows both access levels before the step, and after it if they changed. PhotoKit shows its prompts asynchronously, so a step's line can be written before its prompt appears. Note every prompt yourself. The log also marks one with `photos: app went inactive during "<step>"` and, once it is answered, `photos: active again after "<step>"; access now …`. Control Centre and a glance at the app switcher look the same, so after each step wait until the buttons are enabled again (about 3 s) before leaving the app. Leaving it (Home, Settings, swiping it away, locking) is logged as `app left the foreground …: not a prompt`, and the `went inactive` line just before it is the same event. Answer each prompt before the phone auto-locks (or set Auto-Lock to *Never* for this section): a lock while a prompt is up is logged as `… the phone locked, or the app was left with a prompt up`, and the answer isn't recorded. Run the section best on 1–2 Nov, before anything is recorded in the app, because step A1 may need a reinstall.

Run it in this order. The access level can be changed at any time in Settings › Apps › SB Spike › Photos. Once the app has asked for read/write access, iOS 27.2 offers *None*, *Limited Access* and *Full Access* there, but not *Add Photos Only* (seen on 1 Nov).
