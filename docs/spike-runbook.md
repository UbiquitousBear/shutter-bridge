# Spike runbook

How to run each step of [spike-plan.md](spike-plan.md) with the spike app and the Mac. The plan says what to find out and what counts as a pass; this page says which button to tap, what the log shows, which measurements are recorded and which fixture files are saved. Results go in [spike-findings.md](spike-findings.md).

How to read the tables:

- **Do** is *tab › section › button* in the spike app (*SB Spike* on the phone), or a camera menu, or **Mac** with the command to run for the code-free steps. The app has five tabs: Wired, Wi-Fi, Bluetooth, Background and Log.
- **Log shows** is what appears on the Log tab. Every button writes there, with the app state (foreground, background, locked) where it matters. The log is kept across launches in `Documents/spike-log.jsonl`.
- **Measurements** are the names recorded on the Log tab. `<net>` is `ap` or `lan`, from the Wi-Fi tab's *Network* picker. On day 10, *Copy measurements table* fills the plan's table from the latest value of each name; the "Day 10: export" section lists which name feeds which cell.
- **Fixtures** are saved on the phone under `Documents/fixtures/a7c2/` and go in the repo under `Fixtures/a7c2/` with the same path: `usb/deviceinfo.bin` on the phone is `Fixtures/a7c2/usb/deviceinfo.bin` in the repo. Saving again replaces the earlier file of the same name. See [Fixtures/README.md](../Fixtures/README.md).
- The Wired tab runs one operation at a time: the other buttons are disabled while it runs, and the overlay at the bottom shows it with a *Stop* button, which ends loops at the next file or chunk. The Wi-Fi tab also runs one camera operation at a time.

The spike app compiles with Xcode 27 for iPhone (the unsigned build in `.github/workflows/spike-build.yml`), but it has not yet run on a phone. Behaviour that only a device can confirm is commented `verify on day 1` in the sources.

## Guided runs (build 8)

The *Guided* tab runs the sessions in [spike-remaining.md](spike-remaining.md) as sequences of the same buttons, with alerts for the physical steps: change the camera's USB mode, pull the cable, lock the phone, press the shutter, switch the camera off. Where the app can see a step happen (the cable pulled, the camera back, the phone unlocked), the alert closes by itself; steps done in another tab (scanning the camera's QR code, typing an IP) wait on the Guided tab with *Done* and *Skip*. Every alert has *Cancel run*, which also stops the running transfer. Each run logs `◆` lines, and at the end its log and the measurements table are on the clipboard to paste into the chat (*Copy report again* and *Share report* on the Guided tab).

Since build 14, also `<link>.copyAll.pauses` [count, every copy; the context gives the paused time and the wall time], `<link>.copyAll.pause.seconds` [s, one value per pause, from the expiry to the *Continue copy* tap, recorded once the continued copy copies a file, pauses again or ends: a *Continue copy* that loses the session before copying a file records nothing, and the next records the pause once; the context has the conditions at the expiry] and `<link>.copyAll.expired` (yes, recorded each time iOS ends the task, an expiry or *Stop* in the Live Activity, with the files and GB done, the active seconds up to then and the conditions in the context) and, from the guided run, `<link>.copyAll.pause.stoppedByTester` (your answer: yes when you stopped it in the Live Activity, so that pause isn't an expiry; also asked when iOS ends the task during *Continue copy*'s reconnect). Over Wi-Fi every copy measurement's context also says whether Creators' App was quit or open in the background ("not asked" from the Wi-Fi tab) and whether Bluetooth recovery was allowed. The contexts say "the default folder" or "a folder chosen in Files", never the folder's name. A `◼ Copy all RAW to Files` line in the Log sums up each run: files, failures, GB, minutes, MB/s and the folder. A run also records `<link>.lifecycle.progressAfterBackground` (when you come back after locking; held back when the copy paused while you were away, see the lock row above), which feeds the lock row, and `bgcontinued.startLatency` and `bgcontinued.ran`, so run it after the lock runs of days 5 and 8, or paste the table first.
